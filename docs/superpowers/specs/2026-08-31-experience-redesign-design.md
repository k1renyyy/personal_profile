# Experience 桌面端浅色版设计规格

日期：2026-08-31

状态：已完成口头设计确认，等待书面规格复核

范围：Experience 区块第一版的视觉与交互实现

## 1. 目标

将 Experience 区块重构为一个清晰、连续的职业叙事界面：用户通过左侧三项垂直 Tabs 选择经历，右侧始终只展示一项对应详情。

本次工作的核心是实现可评审的设计骨架，而不是录入正式履历内容。公司、职位、地点、日期、简介和成果均使用占位内容；后续再通过 Sanity 填写和维护真实内容。

## 2. 不可变约束

- 不改变现有 Next.js App Router、React、Tailwind CSS、页面路由、全局布局或静态导出方式。
- 不改变其他页面区块的 DOM、样式、滚动行为、动效或内容。
- 保留现有 `ScrollSection` 对整个区块的进入动画，不重写全局滚动体系。
- 只重构 Experience 区块内部的组件结构和表现。
- 使用现有设计 token 和通用工具，不修改全局主题来适配单一区块。
- 第一版仅以浅色背景和桌面网页为验收范围。深色主题和移动端适配属于后续需求。
- 不在本次引入 Sanity schema、查询、客户端、数据适配器或新的状态管理方案。

## 3. 本次范围

### 包含

- Experience 标题和桌面端双栏布局。
- 三项垂直 Tabs 及其选择、鼠标、焦点和键盘交互。
- 单一详情面板及切换动效。
- Logo、公司名称和日期的视觉层级。
- 详情内的职位元信息、简介和数字编号成果列表。
- Logo 缺失或加载失败时的稳定回退表现。
- reduced-motion 行为。
- 桌面端浅色主题的 Playwright 交互与视觉验证。

### 不包含

- 真实履历内容迁移或最终文案编辑。
- Sanity 集成和内容模型设计。
- 深色主题。
- 移动端布局与移动端验收。
- URL 查询参数或路由驱动的选中状态。
- Storybook、Chromatic、Percy或新的全局 UI 框架。
- Projects 区块的实现；该区块另行设计和评审。

## 4. 内容与数据边界

组件内部暂时使用一个最小的本地占位数据数组，以便完整演示三个 Tab 的切换。每项保持下列稳定字段形状：

```ts
type ExperienceItem = {
  id: string;
  company: string;
  role: string;
  location: string;
  dateRange: string;
  summary: string;
  highlights: string[];
  logo?: {
    src: string;
    alt: string;
  };
};
```

占位数据只验证布局所需的典型长度差异，包括短公司名、较长职位、一段简介以及不同数量的成果项。它不使用或改写现有内容草稿中的网易互娱、bilibili、姚基金履历文本。

为避免过早设计 Sanity，当前组件只消费上述简单数组，不创建 CMS 专用类型、映射层或异步状态。后续接入 Sanity 时，应让查询结果适配这一展示契约；Experience 的视觉组件无需因内容来源变化而重构。

## 5. 页面结构

### 5.1 区块标题

双栏内容上方保留统一的区块标题：

- 英文主标识：`EXPERIENCE`
- 中文辅助标识：`工作经历`

标题沿用现有页面的字体、字号体系和容器宽度，不为 Experience 建立新的全局标题规则。

### 5.2 桌面布局

- 标题下方为两列布局。
- 左列固定宽度 `320px`。
- 右列占据剩余可用空间。
- 两列之间使用现有页面间距尺度形成明确但不过度分离的留白。
- 详情高度由当前内容自然决定，不设置为最长内容高度，不固定高度，也不对高度变化做动画。
- 切换后，下方页面内容随详情高度自然回流，浏览器滚动位置不主动调整。

第一版的实现可以保留不属于验收范围的安全降级断点，防止窄视口发生严重溢出，但不得为移动端另行设计或验收横向 Tabs。移动端的正式交互方案将在后续阶段单独确认。

## 6. 左侧垂直 Tabs

左侧始终展示三项。每项是一个可见、可聚焦的完整 Tab 触发器，采用横向结构：

1. `48px × 48px` 的方形 Logo 容器；
2. 公司名称，作为主要标签；
3. 日期范围，作为次级信息。

不显示“公司名称：”或“时间：”等字段前缀，避免呈现为后台表单。

### 6.1 状态表达

当前项同时使用三种提示，避免依赖 Logo 或颜色单独传达状态：

- 左侧 `2px` 强调线；
- 实心索引点；
- 非常轻微的背景明暗变化。

非当前项保持清晰可读。Hover 和 focus-visible 使用现有颜色 token；键盘焦点必须明显且不能被 active 样式覆盖。整体不采用默认 shadcn 的圆角胶囊或后台管理界面风格。

### 6.2 Logo

Logo 只承担识别辅助作用，公司名称始终可见并作为 Tab 的主要可访问名称。

本次占位实现使用可替换的演示图形或稳定回退字形，不提交用户提供的正式公司 Logo，也不把临时下载路径写入代码。Logo 缺失或加载失败时，在同一个 `48px` 容器内显示公司名称首字或中性占位符，布局不得位移。

后续录入正式内容时，可以将用户批准的资产复制到 `public/images/experience/`，但资产落盘和命名不属于本次设计实现。

## 7. 右侧单一详情面板

页面初次加载默认选择第一项，任意时刻有且只有一个详情面板可见。

详情内容顺序固定为：

1. 职位或角色标题；
2. 公司、地点和日期元信息；
3. 一段工作简介；
4. 完整的数字编号成果列表。

这里的“连续职业叙事”指一个结构连贯的详情面板，不代表把成果合并成长段文字。成果始终分点展示，不添加技术栈或技能标签。

### 7.1 成果列表

- 编号使用 `01`、`02`、`03` 的两位数格式，并随数组长度自然延续。
- 编号位于独立的窄列，正文位于其右侧。
- 各项使用中等垂直间距。
- 项目之间使用低对比度细分隔线，最后一项之后不显示分隔线。
- 不限制成果数量，也不为了占位数据预留固定空白。

## 8. 组件与工具选择

### 8.1 shadcn/ui Tabs 与 Radix Tabs

项目已有 shadcn 的本地源码分发结构、`components.json`、`components/ui/`、`cn` 和 Tailwind 配置。Tabs 作为本地组件加入现有 `components/ui/`，不会引入第二套应用框架。

Radix Tabs 只负责未样式化的交互语义、ARIA 状态和键盘行为；Experience 自己定义视觉样式。这样可以减少自行编写 Tab 状态、焦点管理和键盘导航代码，同时避免将第三方默认视觉扩散到其他区块。

### 8.2 Framer Motion

详情切换沿用项目已经存在的 `framer-motion`，不新增动效库，也不与 `motion/react` 混用。Experience 内部只由 Framer Motion 控制详情切换；外层 `ScrollSection` 继续由现有 GSAP 控制区块进入。

同一个详情节点不得同时由 GSAP 和 Framer Motion 修改 `opacity` 或 `transform`。

### 8.3 Playwright

Playwright 已是项目的浏览器回归工具。本次只增加 Experience 相关用例和必要截图，不引入新的测试或视觉回归平台。

这些选择均局限在 Experience 内部，不修改全局组件 API、样式工具、其他区块依赖或页面框架。

## 9. 交互与可访问性

- Tabs 使用垂直方向语义。
- 点击任一 Tab 后，只显示对应面板。
- `ArrowUp` 和 `ArrowDown` 在三项之间移动。
- `Home` 跳到第一项，`End` 跳到最后一项。
- 三项内容均为即时本地切换，采用自动激活模式。
- Tab 的可访问名称来自可见公司名称，不来自 Logo 的装饰文字。
- Logo 使用恰当的装饰或辅助 alt 策略，避免屏幕阅读器重复朗读公司名。
- 语义关系和选中状态由 Radix Tabs 提供，不用普通按钮模拟。

## 10. 动效

详情切换时长约 `220ms`，允许在 `180–250ms` 范围内微调。表现为：

- 淡入；
- 小幅纵向位移；
- 不做横向滑动；
- 不做容器高度动画。

复用项目现有的 `useHydrationSafeReducedMotion`。当用户偏好 reduced motion 时，详情直接切换，不进行纵向位移；允许只改变透明度，但不得保留明显空间移动。

## 11. 视觉兼容原则

- 使用现有浅色背景、文本色、边框色和强调色 token。
- 字体和排版层级服从当前页面，不为 Experience 引入新的字体。
- 控件外观保持内容型个人站风格，避免卡片堆叠、重阴影、强渐变和管理后台式 Tabs。
- Logo 色彩不作为整个区块的主题色来源。
- Experience 的局部状态样式不得覆盖通用按钮、链接或其他区块选择器。

## 12. 失败与边界行为

- 若 Logo 无来源或加载失败，显示稳定字形回退，公司名称和日期仍完整可见。
- 若简介较长，详情自然增高，不截断。
- 若成果数量不同，列表和下方内容自然回流。
- 占位数组在开发时固定为三项，以匹配本次已确认的设计；不额外设计空状态或加载状态，因为本次没有异步数据源。
- 切换 Tab 不改变 URL、不触发页面滚动、不影响其他区块状态。

## 13. 验收标准

### 13.1 功能

- 初始只显示第一项详情。
- 点击三个 Tab 均可显示唯一对应面板。
- 键盘方向键、Home 和 End 工作正常。
- Tab、面板和选中状态具有正确的可访问语义。
- Logo 缺失或失败时不发生布局位移，Tab 仍可理解和操作。
- 切换不修改 URL，也不主动改变滚动位置。

### 13.2 视觉

在浅色主题下验证：

- `1024 × 768`
- `1440 × 900`
- `1920 × 1080`

三个视口均应保持 `320px` 左列、单一右侧面板、清晰状态标识和无横向溢出。截图覆盖默认状态与至少一次切换后的状态。

### 13.3 动效

- 标准模式下切换约 `220ms`，仅包含透明度和小幅纵向位移。
- reduced-motion 下没有明显位移。
- 详情高度不做动画。
- 外层进入动画与内部切换不存在 `opacity` 或 `transform` 竞争。

### 13.4 回归

- 严格 lint 通过。
- 生产构建通过。
- Experience 的 Playwright 用例通过。
- 现有页面和项目路由测试不因该区块重构失败。
- 其他区块的视觉和交互未被修改。

## 14. 预期实现边界

实现预计只涉及以下类别的文件：

- Experience 区块组件；
- 一个本地 shadcn/Radix Tabs primitive；
- Experience 的本地占位数据或同文件常量；
- Experience 相关 Playwright 测试与评审截图。

若实现需要修改全局布局、主题 token、滚动基础设施、其他区块或 Sanity 基础设施，应停止并重新评审，而不是扩大本规格范围。
